# 信号灯 SignalLight · 产品与技术总体规划 v2

> 定位：**给新手的“技术分析翻译器”**。把专业指标翻译成一句人话：现在怎样、为什么、以前灵不灵、错了在哪认错。
>
> v1（已完成，见 `docs/VALIDATION.md`）：加密市场 10 个币、7 个分析模块、红绿灯结论、历史胜率、仓位计算器、新手学堂。
> v2（本规划）：在 v1 基础上补齐**多周期一览、全站知识点读、历史回放、管理后台（调参 / AI / 日志）和一键部署**。

---

## 1. 竞品对照与差异化

| 维度 | TradingSignal.pro | 信号灯 |
|---|---|---|
| 目标用户 | 老手 + AI Agent（MCP） | **新手** |
| 结论形式 | 各模块分开呈现，术语多 | **红绿灯 + 一句人话**，四个方面汇总成一个结论 |
| 可信度 | 只在 AI 文案里简单复盘一次 | 每个信号都附**历史胜率 vs 随机胜率**、样本数、平均收益 |
| 风控 | 无 | 每个结论给**认错位**，配**仓位计算器（2% 法则）** |
| 解释 | 部分方法有静态释义 | **每个指标、方法、术语**都有：是什么 / 此刻说明什么 / 怎么用 / 常见误区 / 在本币上灵不灵 |
| 多周期 | TD 有多周期表，其他模块各看各的 | **每个模块**都有“多周期一览”，并有跨周期的总结论 |
| 历史回放 | 只有支撑阻力模块支持点 K 线回溯 | **所有模块**都支持“时光机”：回到任意 K 线，看当时的结论后来对不对 |
| 调参 | 有（对用户开放） | 管理员调参，**调整后立即显示胜率前后对比**，并带过拟合提醒 |
| 算法暴露 | 网页接口返回大量中间数据 | 只返回展示所需的结果，核心权重留在服务端 |

## 2. 全站统一规则（每个模块都要遵守）

### 2.1 多周期
- 周期：15m / 1h / 4h / 1d / 1w。**5m 只在专业模式显示**（对新手噪音太大）。
- 页面顶部的“分析周期”切换，对所有模块生效。
- 每个模块右栏的第一张卡片都是**「多周期一览」**：一行 5 格，显示该模块在每个周期上的状态（例如 TD：`涨 5/9`、趋势：`震荡 −8`、斐波那契：`回撤 38%`、缠论：`最近 3卖`、支撑阻力：`最近支撑 −1.9%`）。点击格子即切换周期。下方配一句跨周期总结，例如“大周期偏多、小周期回调，是顺势找买点的时机”。
- 支撑阻力模块额外区分**分析周期**和**图表周期**：例如在 1h 图上查看 4h 算出的关键位（和竞品一样）。

### 2.2 知识点读（每个指标都能一眼看懂）
建立统一知识库 `src/lib/knowledge/`，按 id 覆盖：28 个指标、14 种支撑阻力方法、TD / 缠论 / 斐波那契术语、红绿灯四个维度、各类统计口径。每个条目包含：

| 字段 | 示例（周/月高低） |
|---|---|
| 一句话 | 上周、上个月的最高价和最低价 |
| 是什么 | 大周期交易者最常参考的价位，很多人会在这里挂单 |
| **此刻说明什么**（动态生成） | 现价距上周高点 +2.0%，正在接近这道阻力 |
| 怎么用 | 接近上周高点时不追高；放量突破后它会变成支撑 |
| 常见误区 | 以为一碰就会反转；其实要看有没有放量 |
| **在本币上灵不灵**（动态生成） | （示意）BTC 4h 过去 N 次触及，其中 M 次出现反应 |

交互：方法徽章、指标卡、术语都可以点击，弹出上面这张卡片（桌面端在原位弹出，手机端从底部弹出）。新手模式默认显示“一句话”，专业模式默认显示数值。

### 2.3 时光机（历史回放）
- 每张图都支持：点击任意 K 线 →“以此刻为截止重新计算”。所有模块（结论、TD、关键位、斐波那契、缠论）都回到当时的状态，图上用阴影标出“之后实际怎么走的”。
- 这是新手建立信任、学习看图的最佳方式，也能直观检验算法。
- 实现方式：服务端以 `asOf` 参数截断 K 线后重新计算，结果按（币, 周期, asOf）缓存。

### 2.4 新手 / 专业模式
| | 新手模式（默认） | 专业模式 |
|---|---|---|
| 周期 | 15m–1w | 加上 5m |
| 文案 | 大白话，隐藏原始数值 | 数值 + 参数 + 全部计数 |
| 图上 | 只显示关键标记（9 / 13、前 2 个关键位） | 全部标记、全部档位 |

## 4. 管理后台详细设计

### 4.1 登录与安全
- 首次安装时由脚本创建管理员账号；密码用 scrypt 加盐哈希，会话保存在 HttpOnly Cookie 中。
- 登录失败 5 次锁定 15 分钟；所有后台写操作都记入审计日志。
- **目前没有域名、使用 HTTP**：密码会以明文经过网络。缓解措施：
  1. 安装时可选开启“后台 IP 白名单”；
  2. 可选“后台只监听本机，通过 SSH 隧道访问”；
  3. 以后有了域名，`install.sh --domain xxx` 会自动配置 HTTPS。

### 4.2 参数调试中心（v2 只对管理员开放）
每个模块一个面板，结构统一：

| 模块 | 可调参数（括号内为默认值） |
|---|---|
| 支撑阻力 | 聚类带宽（0.6×ATR，最小 0.25%）；各周期权重（15m 0.5 / 1h 0.75 / 4h 1 / 1d 1.5 / 1w 2）；14 种方法的开关和权重；每侧显示档位数（4）；最小间距（1.5×带宽） |
| TD 序列 | Setup 长度（9）、比较根数（4）、Countdown 长度（13）、是否启用回收规则（否） |
| 指标共振 | 28 个指标的开关；RSI / KD / CCI 等阈值；强共振门槛（指标数的 40%） |
| 趋势强度 | 10 个投票指标的权重；ADX 下限；DI 优势门槛（10%）；标签分界（±15 / ±45） |
| 红绿灯 | 四个维度权重（40 / 25 / 20 / 15）；红绿阈值（±18） |
| 统计 | 各周期的验证窗口（15m 16 根 / 1h 24 / 4h 18 / 1d 10 / 1w 4） |

功能：
- 每个参数都显示默认值和说明；支持单项重置、整个模块重置、全部重置。
- **试算**：保存前先用新参数重算 BTC、ETH，并排展示关键位、结论和各信号胜率的变化。
- **过拟合提醒**：如果只是历史胜率变好，而样本数变少或变化集中在少数信号上，就给出警告。
- 每次保存生成一个版本（谁、什么时候、改了什么），可以一键回滚到任意版本。
- 参数以 JSON 保存在数据库里，引擎从统一的 `getParams()` 读取；未设置的项回落到代码里的默认值。

### 4.3 AI 解读与配置
- **配置页**：服务商（v2 先接 Claude，即 Anthropic 接口格式）、API Key（用服务器主密钥做 AES-256-GCM 加密存储，页面只显示“已配置”）、Base URL（可选，兼容第三方代理）、模型名（可选）、超时时间、每日调用上限。支持“测试连接”，可设置备用模型。
- **生成策略**：输入是引擎算好的结构化快照（各周期红绿灯、TD 状态、关键位、近期信号及其胜率），不传原始 K 线。每个（币, 周期, K 线收盘时间）只生成一次并缓存，同一根 K 线内重复访问不会重复扣费。
- **内容规则**（写进系统提示词，管理员可以改，也能恢复默认）：用新手能懂的话；不预测具体价格；必须写出“如果判断错了，在哪认错”；说明多周期之间是否矛盾；结尾附免责声明。
- **展示**：总览页的结论卡下方显示“AI 解读”，附生成时间和“基于哪根 K 线”；没有配置 AI 时自动隐藏，不影响其他功能。
- **监控**：每次调用的耗时、token 用量、成败都记入日志；后台显示当天用量。

### 4.4 日志中心与监控
**记录内容（统一结构）**：时间、级别（debug / info / warn / error）、分类、消息、追踪 ID、耗时，以及上下文 JSON。

| 分类 | 记录什么 |
|---|---|
| `datasource` | 每次请求交易所：地址、耗时、状态码、是否切换到备用源 |
| `engine` | 每次分析：币、周期、K 线数量、耗时、异常 |
| `ai` | 模型、耗时、token、成败、是否命中缓存 |
| `http` | 前台和接口请求：路径、状态码、耗时、IP（脱敏） |
| `audit` | 后台登录和所有配置修改（修改前后对比） |
| `system` | 启动、定时任务、清理、备份、内存与 CPU 采样 |
| `client` | 浏览器端的报错（自动上报） |

**页面功能**：
- 按时间范围、级别、分类、关键字筛选；点击追踪 ID 查看一次请求的完整链路。
- 健康面板：各数据源的成功率和平均耗时（24 小时）、最近一次成功的时间、错误数趋势、进程运行时长。
- **保留策略**：默认 90 天，可设置为 7 至 365 天；每天凌晨自动清理并压缩数据库；数据库超过设定上限（默认 2 GB）时，提前清理最旧的 debug 和 info 日志。
- **导出**：按时间段和条件导出 CSV 或 JSON；可开启“每周自动归档”（打包成 gzip 存到 `data/archive/`，之后再按保留策略删除）。
- **告警（可选）**：数据源连续失败、错误率突增、AI 额度用尽时，推送到 Telegram。

## 5. 技术架构

```
浏览器 ──HTTP──▶ Next.js 服务（单进程，systemd 守护）
                   ├─ 前台页面 / 接口 ──▶ 分析引擎（纯函数，读取 getParams）
                   ├─ 后台页面 / 接口 ──▶ 鉴权中间件
                   ├─ 数据源适配器：Binance 镜像 → OKX → Bybit（依次回退）
                   ├─ 后台任务（进程内调度）
                   │    · 每分钟：预计算 10 币 × 5 周期并缓存
                   │    · 每天：日志清理、数据库备份、K 线增量入库
                   └─ SQLite（WAL 模式）  data/signallight.db
```

- **为什么用 SQLite**：单台服务器、零运维、备份就是复制一个文件；读写量远低于它的上限。以后需要多台服务器时再换成 Postgres（数据访问层统一封装，替换成本低）。
- **K 线入库**：本地保存长期历史，让胜率统计的样本更多（例如 4h 可回看 2 年），同时减少对交易所的请求。
- **预计算**：用户打开页面时直接读缓存，响应时间小于 100ms，也不会被交易所限流。

### 数据表

| 表 | 用途 |
|---|---|
| `admins` | 管理员账号 |
| `sessions` | 登录会话 |
| `params_versions` | 参数版本（JSON、作者、时间、备注），当前版本为最新一条 |
| `ai_config` | AI 配置（API Key 加密存储） |
| `ai_cache` | AI 解读缓存（币, 周期, K 线时间 → 内容, 模型, token） |
| `logs` | 日志（按时间和分类建索引） |
| `klines` | K 线历史（币, 周期, 时间 → OHLCV） |
| `settings` | 系统设置（日志保留天数、数据源顺序等） |

## 6. 部署与运维（Ubuntu 24.04，韩国服务器，IP + 端口访问）

### 6.1 一键安装 `scripts/install.sh`
```bash
curl -fsSL https://raw.githubusercontent.com/linlea666/pro/main/scripts/install.sh | sudo bash
# 或者先 clone 再执行：sudo bash scripts/install.sh --port 3000
```
脚本依次完成：
1. 检查系统版本、CPU 架构、内存和磁盘；
2. 安装 Node 22（NodeSource）、git、sqlite3；
3. 创建专用系统用户 `signallight`，把代码拉取到 `/opt/signallight`；
4. 测试能否访问各数据源（Binance、OKX、Bybit），把结果打印出来；
5. 生成 `.env`：随机的会话密钥和加密主密钥（权限 600）；
6. `npm ci && npm run build`，初始化数据库；
7. 交互式创建管理员账号（也可以通过参数传入）；
8. 写入 systemd 服务：开机自启、崩溃自动重启，日志同时写入 journald；
9. 用 ufw 放行端口（例如 3000）；
10. 健康检查通过后，打印访问地址 `http://服务器IP:3000` 和后台地址。

### 6.2 一键更新 `scripts/update.sh`
1. 备份数据库到 `data/backups/`（保留最近 10 份）；
2. 记录当前版本号，然后 `git pull`；
3. `npm ci && npm run build`（构建失败时不影响正在运行的服务）；
4. 执行数据库迁移；
5. 重启服务，并在 60 秒内反复检查 `/api/health`；
6. **健康检查失败就自动回滚**到上一个版本和备份的数据库，并打印原因。

### 6.3 其他脚本
| 脚本 | 用途 |
|---|---|
| `scripts/rollback.sh` | 手动回滚到指定版本 |
| `scripts/backup.sh` | 手动备份（每天也会自动备份一次） |
| `scripts/reset-admin.sh` | 忘记密码时在服务器上重置管理员 |
| `scripts/status.sh` | 查看服务状态、最近错误日志、数据源连通性 |

### 6.4 服务器位置
韩国服务器通常可以访问 Binance 公共行情和 OKX，但以实测为准：安装脚本会逐个测试，不通的数据源会自动跳过。中国大陆服务器无法访问这些数据源，美国服务器会被 Binance 屏蔽。

## 8. 合规与边界
- 全站显著提示“仅供学习参考，不构成投资建议”；AI 输出也强制带上这句话。
- 不接入下单功能，不承诺收益；样本不足的统计必须标注。
- 数据来自交易所公开行情接口；不抓取、不复制竞品的数据或文案。
